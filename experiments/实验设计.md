# 实验设计：AI 论文结论回答中的"限定条件遗漏"核查

> 状态：**已执行**（2026-10-24，论文 arXiv:2610.28675v1）。本地隔离子代理实验与玻尔科学空间复测（A/B 各一次）均已完成，结果见 `verification/`；玻尔端部分运行元信息未留存，见 `bohrium/待回传-说明.md`。
> 本文件是可复现实验的协议。执行时不得事后修改条件定义；如确需调整，在文末"修订记录"注明原因与日期。

## 1. 研究问题

日常用 AI 读论文时，最常见的风险不是 AI"说错"，而是 AI"说得对但不完整"：结论被复述出来，限定条件（数据集、任务范围、模型规模、硬件、超参、假设）被悄悄丢掉，读者因此把论文结论过度泛化。

本实验回答三个问题：

- **RQ1**：常见的"朴素提问"（如"总结这篇论文的结论"）会让 AI 遗漏多少限定条件？
- **RQ2**：把"证据锚定 + 限定条件显式化"写进提示词后，遗漏是否减少？减少多少？
- **RQ3**：两种条件下，AI 是否输出无原文依据的内容？

## 2. 方法与设计取舍

- **对照设计**：同一论文全文、同一提示问题域、两种提示词（A 朴素 / B 结构化）。除提示词外其余条件保持一致（同一模型、论文全文一次性提供、互不共享对话历史）。
- **执行环境一（主实验）**：隔离子代理（ZCode general-purpose agent）。子代理只收到【论文文本 + 提示词】，不携带任何本实验相关对话历史，等价于真实用户"新开对话"的场景。选择它的原因：实验条件干净、输入输出可完整存档、可被他人复现。
- **执行环境二（玻尔科学空间）**：由论文作者在网页端用完全相同的提示词重跑 A/B，记录模型名与原始对话导出。两个环境互为印证：子代理证明"条件可控"，玻尔证明"真实产品环境同样成立"。
- **评估方法**：由 ZCode AI 主代理（发布者指导下）对照论文 PDF 原文逐条核查。限定条件的 ground truth 由主代理**先行**从原文整理（先做 ground truth 再看 AI 输出，避免被 AI 带偏；AI 参与声明见 README §7.2）。

## 3. 条件定义

### 条件 A（朴素提问，baseline）
见 `prompts/条件A-朴素提问.md`，逐字使用。模拟最常见的日常用法。

### 条件 B（结构化提问）
见 `prompts/条件B-结构化提问.md`，逐字使用。核心约束：
1. 每条结论必须附原文位置（页码/章节/图表号）与短引文；
2. 每条结论必须单列"成立条件"；
3. 必须区分【论文声明】【实验支持】【作者推测】；
4. 无依据不写、不确定标注"依据不足"。

## 4. 执行步骤

1. 论文 PDF 放入 `paper/`，记录：题名、作者、版本（arXiv vX / DOI / 出版信息）、获取日期、许可证与可分享范围。
2. 按 `verification/核查记录模板.md` 第一步，**人工**整理"原文限定条件清单"（ground truth）。
3. 启动隔离子代理：粘贴条件 A 提示词 + 论文全文，完整输出存档为 `experiments/A1-输出.md`（输入存档为 `experiments/A1-输入.md`）。
4. 同法执行条件 B，存档 `experiments/B1-输入.md`、`experiments/B1-输出.md`。
5. 对照核查，填写两份核查记录（`verification/核查记录-条件A.md`、`-条件B.md`）。
6. （玻尔生态）按 `prompts/玻尔操作步骤.md` 在玻尔科学空间重跑 A/B，记录回传至 `bohrium/`，用同一模板核查。
7. 汇总统计并写入正文：
   - 限定条件覆盖率 = AI 保留的限定条件条数 ÷ ground truth 条数；
   - 无依据陈述条数；错误条数（与原文相悖）。

## 5. 命名与存档规范

- `experiments/Xn-输入.md` / `Xn-输出.md`：条件 X 第 n 次运行的完整输入输出；
- `bohrium/`：玻尔端导出的对话记录与截图；
- 所有输出文件头部必须记录：日期、执行环境、模型名称（未知则写"界面未显示"）。

## 6. 诚信规范

- 论文原文、AI 输出、作者判断在所有材料中显式区分；
- 未完成的验证一律标"未完成"，不得写成已完成；
- 模型版本、成本无法获知时如实说明；
- 不因结果"不好看"而重跑挑选；若重跑，全部运行一并存档并说明。
